# How It Works

Author a media program, then play it live or export files. The pipeline below is for extenders who need the compile and export boundary.

## Authoring to play or export

```text
*.media.ts media program
      ↓
source analysis
      ├── server-only entries projection
      └── browser-safe media projection
                    ↓
               MediaDefinition
          ┌─────────┴─────────┐
     Player (live)     entry × variant × edition
                              ↓
                       Media IR schema 0
                              ↓
                 destination/custom rendition
                              ↓
                      atomic export bundle
```

For ordinary media, the browser Player and server export both evaluate the same deterministic render function.

For collections, the compiler extracts `entries` before browser module resolution. Provider imports, static datasets, Node dependencies, secrets, and raw entry data are excluded from browser bundles, artifacts, IR, and sourcemaps. The server resolves and freezes the complete entry snapshot once, then reuses it across all planned renditions.

Destinations do not enter `render(ctx)`. They turn the authored media into a requested canvas and encoding after the entry, variant, and edition coordinates are known.

The resulting URL-free schema-0 bundle records coordinates, hashes, dimensions, MIME types, producer identity, and paths. It records entry ids and data digests, never raw collection data.
