# Player

The passive Player evaluates a deterministic media definition in the browser, lowers its typed media tree, and paints the resulting HTML/SVG into a sandboxed surface. It accepts live data, seek/play controls, and canvas size. It does not own export destinations or interactive scene behavior.

```ts
import { Player } from "@foxworth/superimg/player";

const player = new Player({ container });
await player.load(launch, { data: { title: "Live preview" } });
player.play();
```

For exact browser capture and optional agent tools, mount the pure
`@foxworth/superimg/inspection` entry. See [Browser inspection](/docs/inspection) for
accepted frames, resource readiness, and persistent inspection mode.

React apps use `@foxworth/superimg/react` for the passive component and playback hooks:

```tsx
import { Player } from "@foxworth/superimg/react/player";
import launch from "./launch.media";

export function LaunchPreview() {
  return <Player media={launch} controls />;
}
```

That surface deliberately does not compile source strings. Browser authoring
shells opt into the compiler graph explicitly:

```tsx
import { CompilingPlayer } from "@foxworth/superimg/react/compile";

export function SourcePreview({ code }: { code: string }) {
  return <CompilingPlayer code={code} controls />;
}
```

`@foxworth/superimg/react/compile` also exports `useCompiler` and
`useCompiledMedia`. Keep it out of ordinary application playback bundles.

Interactive explainers use `InteractivePlayer` from `@foxworth/superimg/react/interactive`; see [Scene guides](/docs/scene-guide). Keeping that path on a separate import means ordinary image/video playback does not carry guide, action, query, or hit-target APIs.
Passing a raw interactive definition to the passive Player fails with
`INTERACTIVE_PLAYER_REQUIRED` instead of silently inventing a playback clock.

Export remains server-side:

```bash
superimg export launch --for youtube
```

## Driven playback

`drive` seeks the same timeline the export uses. Two values. Springs are fixed.

```ts
new Player({ container, drive: "scroll" });   // page story — sticky player, tall parent
new Player({ container, drive: "pointer" });  // scrub / follow — X across the box
```

Author nothing about drive. `ctx.timeline.progress` is the clock. Prefer **one lockup, many materials**: teach the mark with a quiet reveal, then cut paint (not position). See `examples/marketing/lockup-tour` and:

- `just example apps/lockup-scroll`
- `just example apps/lockup-pointer`

`hoverBehavior: "preview-scrub"` stays for gallery cards. Heroes use `drive`.

`Plate({ src })` is only for a photoreal subject that already exists as a short clip. Compile with `superimg plate <file>` (atlas, ≤6s). Page / `Fill` owns the background. Do not generate video in the framework.
