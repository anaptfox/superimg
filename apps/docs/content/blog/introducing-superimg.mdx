# Introducing SuperImg

SuperImg treats media as code: a deterministic TypeScript `render(ctx)` that returns HTML or SVG. The same media program plays live in the passive Player and exports to platform-ready files.

<CodeDemo exampleId="intro" />

The concise helpers make the common path small:

```ts
import { video } from "@foxworth/superimg";

export default video({
  duration: "6s",
  render(ctx) {
    return `<h1>Hello at ${ctx.timeline.seconds.toFixed(2)}s</h1>`;
  },
});
```

Use `image()`, `svg()`, and `ogImage()` for the other media kinds. Use bare `define()` when you need the lower-level contract.

## One story, several delivery targets

Media content never names platforms or codecs. The root render responds to `ctx.width` and `ctx.height`; exact-aspect editions can replace its art direction. Delivery is selected when exporting:

```bash
npx superimg export launch.media.ts --for youtube --for instagram-square
npx superimg export launch.media.ts --for 1080x1920.mp4
```

## Batch materialization

Collections run the same deterministic program for every entry:

```ts
export default collection({
  entries: loadEpisodes,
  media: video<Episode>({
    duration: "12s",
    render: (ctx) => renderEpisode(ctx.data),
  }),
});
```

The compiler keeps the provider, Node dependencies, and raw dataset out of browser programs and artifacts.

## Interactive experiences

Guides, semantic scenes, actions, and navigation live in `@foxworth/superimg/interactive/define`. An interactive definition is one live experience whose data comes from the host; it is not a collection.
